# please-humanize

한국어 업무 메시지와 기술 문서를 자연스럽고 읽기 쉽게 다듬는 AI 스킬입니다.

명사만 길게 나열하거나 번역투로 늘어진 문장을 구체적인 행동으로 풀어 씁니다. 원문의 사실, 날짜, 조건, 시제와 불확실성은 유지합니다.

## 언제 쓰나요

글을 새로 쓸 때보다, 이미 있는 글이 어색해서 고쳐야 할 때 쓰는 스킬입니다.

- 뜻은 맞는데 읽기 어려운 글. `정합성 확보를 위한 검증 수행`처럼 명사 안에 동작이 숨어 있는 문장이 이어질 때
- AI가 쓴 초안. 문장은 매끄럽지만 같은 결론을 세 번 바꿔 말하거나, 원문에 없던 이유와 효과가 들어가 있을 때
- 개발 업데이트, 릴리즈 노트, 기능 설명. 변경 내용은 다 적혀 있는데 무엇을 먼저 봐야 할지 모르겠을 때
- 슬랙 메시지, 업무 메일, 고객 안내, 동료 피드백. 정중하게 쓰려다 요청이 흐려졌거나, 거절과 일정 경계가 뭉개졌을 때
- 번역투 교정. 쉼표를 어미마다 넣었는지, 날짜와 띄어쓰기 표기가 맞는지 함께 보고 싶을 때

## 설치

이 저장소는 SKILL.md 형식의 스킬 원본입니다. 독립 실행 프로그램이나 앱별 플러그인 패키지는 아닙니다.

1. 저장소의 파일을 다운로드합니다.
2. `please-humanize` 폴더 안에 `SKILL.md`와 `references` 폴더가 함께 있도록 유지합니다.
3. 사용하는 AI 도구의 스킬 가져오기·설치 절차에 따라 이 폴더를 등록합니다. 지원 형식과 설치 방법은 해당 도구의 안내를 확인하세요.

파일을 읽을 수 있는 AI 도구에서 설치 없이 시험하려면 `SKILL.md`와 참고 문서 2개를 모두 첨부하고 "첨부한 스킬 지침에 따라 아래 글을 다듬어줘"라고 요청할 수 있습니다. 이 방법은 해당 대화에서 지침을 제공하는 것이며 영구 설치와는 다릅니다.

GitHub 공개만으로 다른 사용자의 AI에 자동 설치되지는 않습니다. 특정 앱에서의 설치·실행은 이 공개 준비 과정에서 검증하지 않았습니다.

## 어떻게 쓰나요

스킬 이름과 다듬을 원문을 함께 보내면 됩니다. 여기에 **지켜야 할 것**을 한 줄 적으면 결과가 훨씬 안정적입니다. 원문의 사실과 조건은 스킬이 알아서 보존하지만, 구조를 얼마나 바꿀지나 분량을 어디까지 줄일지는 판단이 갈리기 때문입니다.

요청에 함께 적으면 좋은 것입니다.

| 적을 것 | 예 |
| --- | --- |
| 글의 종류와 독자 | `PM과 배포 담당자가 같이 보는 릴리즈 노트야` |
| 유지할 것 | `목차와 티켓 번호, 표는 그대로 둬` |
| 격식 | `외부 고객한테 보내는 메일이야` / `친한 동료한테 보내는 슬랙이야` |
| 범위 | `문서 전체` / `03절만` |

이렇게 요청할 수 있습니다.

- `please-humanize로 이 릴리즈 노트 다듬어줘. 버전과 조건은 그대로 두고 순서만 읽기 쉽게 바꿔줘.`
- `please-humanize로 이 슬랙 메시지 다듬어줘. 정중하게 쓰되 이번 주엔 어렵다는 건 분명히 남겨줘.`
- `please-humanize 기준으로 쉼표와 표기만 봐줘. 문장 구조는 건드리지 말고.`

스킬은 글의 종류를 보고 참고 문서를 골라 읽습니다. 기술 문서와 릴리즈 노트에는 `references/technical-writing.md`의 순서를, 표기·쉼표·번역투 교정에는 `references/korean-style.md`의 기준을 적용합니다. 메일과 슬랙에는 `SKILL.md`의 메시지 처리 순서를 씁니다.

## 다듬는 기준

1. 핵심 상태나 변경 사항을 먼저 설명합니다.
2. 독자가 이해할 순서로 정보를 배치합니다.
3. 불필요한 명사 나열, 반복 설명과 과도한 수동 표현을 줄입니다.
4. 이유·조건·결과를 자연스럽게 연결하고 필요한 곳에만 쉼표를 씁니다.
5. 가능성을 확정으로, 계획을 완료로 바꾸지 않습니다.
6. 글의 종류와 상대에 맞게 격식을 조절합니다.

## 사용 예시

아래는 설명을 위해 만든 예시입니다. 결과는 사용하는 모델과 문맥에 따라 달라질 수 있습니다.

**기술 문서**

> **요청** — please-humanize 스킬로 아래 개발 업데이트를 다듬어줘. 조건과 시제는 유지해줘.
>
> 이번 버전부터 파이프라인 실행 성공 시 중간 파일의 즉시 삭제가 수행되도록 변경되었습니다. 이를 통해 실행 종료 후에도 스토리지에 파일이 누적되는 문제가 해결되었습니다.

> **다듬은 결과**
>
> 이번 버전부터는 파이프라인 실행에 성공하면 중간 파일을 바로 삭제하여 실행 후에도 스토리지에 파일이 쌓이는 문제를 해결했습니다.

**업무 메시지**

> **요청** — please-humanize 스킬로 아래 슬랙 메시지를 다듬어줘. 정중하게 쓰되 이번 주에는 대응하기 어렵다는 점은 분명히 남겨줘.
>
> 이번 주는 진행하는 일이 많아서 요청하신 작업 못 할 것 같아요.

> **다듬은 결과**
>
> 현재 진행 중인 작업이 있어 이번 주에는 요청하신 작업을 맡기 어렵습니다. 다음 주 일정이 정리되면 다시 알려드리겠습니다.

## 이 스킬이 하지 않는 것

- 원문에 없는 이유, 수치, 일정, 담당자를 만들지 않습니다.
- 확인 중인 일을 완료로, 전망을 확약으로 바꾸지 않습니다. 확정된 실패를 `실패할 수 있습니다`로 약화하지도 않습니다.
- `인증`, `배포`, `동기화`처럼 정확하고 익숙한 기술 용어를 쉬운 말로 바꾸지 않습니다. 코드 식별자, 버전, 파일명, ISO 날짜 표기도 그대로 둡니다.
- 메시지를 대신 보내지 않습니다. 문안만 제공합니다.
- 문체를 다듬는 일이며 구현이나 사실 관계를 검증하지는 않습니다.
- 규범에서 허용하는 여러 표현 중 하나를 선호할 뿐, 다른 표현을 틀렸다고 단정하지 않습니다.
