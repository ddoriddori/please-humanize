# please-humanize

한국어 업무 메시지와 기술 문서를 자연스럽고 읽기 쉽게 다듬는 AI 스킬입니다.

명사만 길게 나열하거나 번역투로 늘어진 문장을 구체적인 행동으로 풀어 씁니다. 원문의 사실, 날짜, 조건, 시제와 불확실성은 유지합니다.

## 이런 글에 사용하세요

- 슬랙 메시지, 업무 메일, 고객 안내와 동료 피드백
- 개발 업데이트, 릴리즈 노트와 기능 설명
- 문장이 장황하거나 문단의 흐름이 어색한 기술 문서

## 다듬는 기준

1. 핵심 상태나 변경 사항을 먼저 설명합니다.
2. 독자가 이해할 순서로 정보를 배치합니다.
3. 불필요한 명사 나열, 반복 설명과 과도한 수동 표현을 줄입니다.
4. 이유·조건·결과를 자연스럽게 연결하고 필요한 곳에만 쉼표를 씁니다.
5. 가능성을 확정으로, 계획을 완료로 바꾸지 않습니다.
6. 글의 종류와 상대에 맞게 격식을 조절합니다.

## 사용 예시

아래는 설명을 위해 만든 예시입니다. 결과는 사용하는 모델과 문맥에 따라 달라질 수 있습니다.

**요청**

> please-humanize 스킬로 아래 개발 업데이트를 다듬어줘. 조건과 시제는 유지해줘.
> 이번 버전부터 파이프라인 실행 성공 시 중간 파일의 즉시 삭제가 수행되도록 변경되었습니다. 이를 통해 실행 종료 후에도 스토리지에 파일이 누적되는 문제가 해결되었습니다.

**다듬은 예시**

> 이번 버전부터는 파이프라인 실행에 성공하면 중간 파일을 바로 삭제하여 실행 후에도 스토리지에 파일이 쌓이는 문제를 해결했습니다.

**업무 메시지 요청 예시**

> please-humanize 스킬로 아래 슬랙 메시지를 다듬어줘. 정중하게 쓰되 이번 주에는 대응하기 어렵다는 점은 분명히 남겨줘.
> 이번 주는 진행하는 일이 많아서 요청하신 작업 못 할 것 같아요.

## 설치와 사용

이 저장소는 SKILL.md 형식의 스킬 원본입니다. 독립 실행 프로그램이나 앱별 플러그인 패키지는 아닙니다.

1. 저장소의 파일을 다운로드합니다.
2. `please-humanize` 폴더 안에 `SKILL.md`와 `references` 폴더가 함께 있도록 유지합니다.
3. 사용하는 AI 도구의 스킬 가져오기·설치 절차에 따라 이 폴더를 등록합니다. 지원 형식과 설치 방법은 해당 도구의 안내를 확인하세요.
4. 등록한 스킬을 선택하거나 이름을 명시하고 다듬을 원문을 전달합니다.

파일을 읽을 수 있는 AI 도구에서 설치 없이 시험하려면 `SKILL.md`와 참고 문서 2개를 모두 첨부하고 “첨부한 스킬 지침에 따라 아래 글을 다듬어줘”라고 요청할 수 있습니다. 이 방법은 해당 대화에서 지침을 제공하는 것이며 영구 설치와는 다릅니다.

GitHub 공개만으로 다른 사용자의 AI에 자동 설치되지는 않습니다. 특정 앱에서의 설치·실행은 이 공개 준비 과정에서 검증하지 않았습니다.

## 처음 GitHub에 올리는 방법

1. GitHub에서 `please-humanize`라는 Public 저장소를 만듭니다.
2. `README.md`, `LICENSE`, `SKILL.md`는 저장소의 맨 위에 올립니다.
3. `references` 폴더를 만들고 그 안에 참고 문서 2개를 넣습니다. 브라우저의 Add file → Create new file에서 파일명에 `references/korean-style.md`처럼 경로를 입력할 수도 있습니다.
4. 내용을 저장한 뒤 README의 문서 링크와 파일 경로를 확인합니다.
5. 저장소 주소를 공유합니다.

파일 업로드 안내: https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository

## 원본과 참고 자료

강다예의 업무 메시지·기술 문서 편집 선호를 정리한 스킬입니다. 스킬 본문과 참고 문서는 기존 원본을 그대로 포함했습니다. 선택적인 화면 표시 설정과 아이콘은 포함하지 않았습니다.

국립국어원의 규범·해설과 개발 블로그를 참고한 출처는 참고 문서 안에 있습니다. 외부 자료는 해당 권리자의 권리를 따르며, 이 프로젝트의 라이선스는 링크된 외부 자료에 적용되지 않습니다. 예시는 공식 규정의 예문이나 실제 고객 발송 문안으로 취급하지 않습니다.
