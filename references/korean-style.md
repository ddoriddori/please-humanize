# 한국어 표기와 표현 지침

## 규범과 문체 선택을 구분하기

맞춤법·띄어쓰기·문장 부호는 국립국어원의 어문 규범과 사전에서 확인하라. 문장이 읽기 쉬운지는 독자, 목적, 문맥과 이 스킬에 정리한 사용자 선호로 판단하라. 규범에서 허용하는 여러 표현 중 하나를 선호한다고 다른 표현을 틀렸다고 단정하지 마라.

국립국어원의 공공언어 자료는 정확성과 이해하기 쉬운 설명을 위한 참고 지침으로 사용하라. 공공기관 문서의 형식이나 법적 의무를 민간 기술 문서에 그대로 적용하지 마라. 오래된 해설과 개별 상담 답변을 현행 규정 전체로 일반화하지 마라.

## 쉼표는 필요한 경계에만 쓰기

- 연결 어미 뒤의 쉼표는 자동으로 넣지 마라. 짧고 인과관계가 분명하면 '설정 항목이 자동으로 생성되므로 별도 설정이 필요하지 않습니다'처럼 이어 써라.
- 앞의 조건이 길거나 절의 경계를 표시해야 오독을 줄일 수 있을 때는 쉼표를 사용할 수 있다. '~므로,'가 무조건 틀리거나 '~므로' 뒤에 반드시 쉼표가 필요하다고 설명하지 마라.
- '~으며', '~면', '~때문에'도 문맥으로 판단하라. 낭독할 때 잠깐 쉬는 곳마다 쉼표를 넣지 마라. 조건·행동·이유가 연이어 복잡해졌다면 문장을 나누는 편을 먼저 검토하라.
- 나열, 삽입, 부름, 숫자 구분 등 다른 용도의 쉼표는 보존하라. 문장 안의 쉼표 개수나 어미를 기준으로 기계적으로 삭제하지 마라.
- '생성되므로,'를 지적받았을 때는 어미·피동·쉼표 중 무엇을 묻는지 확인하고 그 부분에 답하라. 사용자의 문체상 불편을 근거 없는 문법 오류로 설명하지 마라.

아래는 이 스킬에서 만든 편집 예시이며 공식 규정의 예문이 아니다.

| 검토할 문장 | 이 문맥에서의 선택 |
| --- | --- |
| 필요한 설정도 생성되므로, 따로 설정할 필요는 없습니다. | 필요한 설정도 생성되므로 따로 설정할 필요는 없습니다. 짧은 이유와 결과를 이어 쓴다. |
| 서비스가 시작되면 설정을 생성하고 갱신을 시작하므로, 별도 설정은 필요하지 않습니다. | 기본 설정에서는 서비스 시작과 함께 키 자동 갱신이 시작됩니다. 필요한 설정 항목도 자동으로 생성됩니다. 복잡한 연결과 반복을 줄인다. |
| 일부 요청은 이전 키를 사용하고 나머지는 새 키를 사용하는 전환 구간에서도 호출이 이어져야 하므로, 직전 키는 일정 시간 함께 허용합니다. | 긴 원인 설명과 결론의 경계를 보여주는 쉼표를 유지할 수 있다. 원문에 전환 동작과 허용 조건이 있을 때만 쓴다. |

## 번역투는 문장 구조부터 다듬기

번역투, 공문체의 장황함, 익숙하지 않은 단어 조합을 모두 문법 오류로 묶지 마라. 어색하게 읽힌다는 이유만으로 특정 외국어에서 유래했다고 단정하지 마라. 아래 기준은 독자가 동작과 관계를 바로 이해하도록 돕는 편집 기준이다.

1. 핵심 동작을 찾아라. 누가 무엇을 확인·저장·변경하는지 원문에서 파악하라.
2. 동작을 가리는 표현을 걷어내라. '~에 대한 확인을 수행하다', '~하는 것을 가능하게 하다'처럼 명사와 보조 설명으로 늘어진 부분은 구체적인 동사로 풀어라. '~에 의해', '~에 있어서', '~를 통해'는 실제 관계를 나타내는지 판단하고 불필요할 때만 줄여라.
3. 명사 앞에 길게 붙인 설명을 조건과 동작으로 풀어라. 변경과 효과가 직접 연결되면 한 문장으로 설명하되 주제나 조건이 겹쳐 복잡해지면 나누어라. '이것은 ~를 의미합니다'가 새 해석 없이 앞말만 반복하면 합치거나 덜어내라. 실제 개념이나 수치의 의미를 설명하는 문장은 보존하라.
4. 동료에게 말하듯 문단을 이어 읽어라. 목적어와 동사가 잘 어울리는지, 불필요한 주어·대명사·소유 표현을 반복하는지, 서술어를 읽기까지 수식어가 너무 많은지 확인하라. 모든 글을 구어체나 짧은 문장으로 통일하지 마라.
5. 원문과 의미를 대조하라. 의도를 성과로, 가능성을 확정으로, 확정 결과를 가능성으로 바꾸지 마라. 문장을 자연스럽게 만들려고 재발급 조건·수행 주체·새로운 효과를 추가하지 마라.

아래는 직접 만든 교정 예시이며 출처의 인용이나 다른 요청의 사실이 아니다. 왼쪽 표현이 언제나 틀렸다는 뜻으로 사용하지 마라.

| 점검할 표현 | 이 문맥에서의 개선 |
| --- | --- |
| 만료 여부에 대한 확인을 수행한 후 재발급을 진행합니다. | 만료 여부를 확인한 뒤 새로 발급합니다. 조건부 재발급인지는 원문에서 확인하라. |
| 이 기능은 사용자가 중간 결과를 확인하는 것을 가능하게 합니다. | 이 기능을 사용하면 중간 결과를 확인할 수 있습니다. |
| 내부 API 키의 갱신은 관리 서비스에 의해 수행됩니다. | 관리 서비스가 내부 API 키를 갱신합니다. |
| 대용량 문서의 처리에 있어서 시간이 오래 걸리는 문제가 있었습니다. | 대용량 문서를 처리할 때 시간이 오래 걸리는 문제가 있었습니다. |
| 큐 대기 중 만료된 인증 정보에 대한 자동 재발급 기능을 추가했습니다. | 큐에서 대기하다 인증 정보가 만료되면 자동으로 새로 발급받도록 했습니다. |
| 직전 키는 1시간 동안 허용됩니다. 이것은 해당 기간에 기존 키의 사용이 가능하다는 것을 의미합니다. | 직전 키는 1시간 동안 사용할 수 있습니다. |
| 정상적인 처리가 중단되지 않도록 하기 위한 목적입니다. | 정상적으로 처리 중인 작업이 중단되는 것을 막기 위해서입니다. |

자연스러운 피동형과 기술 용어는 유지하라. '방식이 변경되었습니다'는 변경 결과를, '중간 파일은 실행에 성공하면 자동으로 삭제됩니다'는 파일의 처리를 설명한다. 행위자를 억지로 추가하지 마라. 'API가 응답합니다', '서버가 요청을 처리합니다'처럼 기술 문맥에 익숙한 표현을 무생물 주어라는 이유로 배제하지 마라. '~하므로', '~할 수 있습니다', '~하게 됩니다'도 문장 역할과 사실에 맞게 선택하라.

## 표기와 문장 점검에 활용하기

- 단어의 뜻·품사·붙여 쓰는 말인지 확신이 없으면 표준국어대사전과 어문 규범을 확인하라. 조사와 의존 명사를 구별하라. '할 수 있습니다', '검토 중입니다'처럼 띄어 쓰되 비슷한 모양의 말을 일괄 치환하지 마라.
- 날짜를 점으로 적는 일반 본문에서는 '2026. 9. 2.'처럼 연·월·일 뒤의 점을 확인하라. 원문의 ISO 날짜, 파일명, 버전, 코드, API 필드, UI의 정확한 표기는 보존하라. 날짜 자체를 바꾸지 마라.
- 주어와 서술어, 목적어와 동사의 관계를 확인하라. 생략 때문에 무엇을 확인하거나 변경하는지 모호하면 원문에서 확인한 성분을 복원하라.
- 낯선 한자어와 명사 나열은 조사와 동사로 풀어라. 독자에게 익숙한 기술 용어까지 쉬운 말로 치환하거나 처음 나올 때마다 정의하지 마라.
- 과도한 피동·사동과 의미 없는 '수행·진행'은 줄이되 '방식이 변경되었습니다', '구조가 적용되었습니다' 같은 자연스러운 변경 설명은 허용하라. 상태·행동·변경 중 문장의 초점을 선택하라.
- 두괄식으로 핵심을 제시한 뒤 필요한 근거를 연결하라. 의무·선택·금지·예외를 구별하고 가능성과 확정 결과를 바꾸지 마라. 문체를 부드럽게 하려고 '실패합니다'를 '실패할 수 있습니다'로 약화하지 마라.
